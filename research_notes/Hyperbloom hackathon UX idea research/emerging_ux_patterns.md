# Emerging & Innovative UX Interaction Patterns (2025–2026) for a Student UI/UX Hackathon

> Research method note (for the report writer): direct page fetches to nngroup.com, w3.org, shapeof.ai and design.google were refused by this session's egress policy (HTTP 403 at the proxy), so findings below come from web-search result extracts of those pages plus secondary sources. Where a claim rests only on a secondary/vendor source, or sources conflict, that is flagged inline. Today's date: 2026-10-10.

## 1. AI-native / agentic UX patterns (generative UI, intent-based UI, agent timelines, editable plans, confidence, explainability, graceful failure, HITL approvals, undo, citations)

### Takeaway
The 2025–2026 AI-UX frontier has moved from "chat box + answer" to (a) generative UI, where the model returns interactive components instead of text (Google Gemini 3 "dynamic view", Vercel AI SDK tool parts, A2UI/MCP Apps protocols), and (b) governable agents: editable plans before execution, visible step timelines, risk-tiered approval gates, checkpoints/rewind, and calibrated uncertainty. The strongest empirical anchor is that first-person hedges ("I'm not sure, but…") measurably reduce over-reliance; the strongest warning is that users rarely click citations, so the mere presence of citations inflates trust.

### Cited Findings

**Pattern libraries / canonical frameworks**
- Shape of AI (Emily Campbell) is a community catalogue of AI interaction patterns; its current site organises patterns into six categories: Wayfinders (suggestion chips, example galleries, templates, nudges, randomize), Inputs (open-ended prompt box), Tuners (attachments, filters, model selection, voice & tone), Governors (citations, action plans, pause/redirect mid-stream), Trust builders (caveats, data-ownership controls, disclosure labels, "footprints" that trace how the AI reached its answer) and Identifiers (AI-specific colour, iconography, name) — [Shape of AI](https://www.shapeof.ai/); [Fountn summary](https://fountn.design/resource/the-shape-of-ai-ux-patterns-for-artificial-intelligence-design/); [amirelion summary](https://amirelion.com/blog/shape-of-ai-pattern-library-ai-ux-design). Older write-ups use different category names (Prompts, Trust Indicators), so categories have evolved — [The Informed Life podcast](https://theinformed.life/2024/05/19/episode-140-emily-campbell/).
- Microsoft's 18 Guidelines for Human-AI Interaction (Amershi et al., CHI 2019) were distilled from 160+ candidate recommendations — [Microsoft Research blog](https://www.microsoft.com/en-us/research/blog/guidelines-for-human-ai-interaction-design). Guideline 8 "Support efficient dismissal" and Guideline 9 "Support efficient correction: make it easy to edit, refine, or recover when the AI system is wrong" — [uxdesign.cc summary](https://uxdesign.cc/guidelines-for-infusing-artificial-intelligence-to-products-bbbcf7b928f7); [Microsoft Research](https://www.microsoft.com/research/blog/guidelines-for-human-ai-interaction-design/).
- HAX Toolkit Guideline 2 ("make clear how well the system can do what it can do") has concrete patterns: 2A match precision of UI language to system performance; 2B match precision of numbers; 2C report system performance info; 2D low-performance alerts; examples catalogued include Copilot in Word/Outlook and Google Gemini — [Microsoft HAX Toolkit pattern library](https://www.microsoft.com/en-us/haxtoolkit/library/pattern/).
- Google PAIR People + AI Guidebook "Explainability + Trust" chapter argues for *calibrated* trust (not maximal trust): users should know when to rely on a prediction vs. their own judgment; both over-trust and "algorithm aversion" are failure modes; deciding whether/when/how to show confidence shapes decisions — [PAIR Explainability + Trust chapter PDF](https://pair.withgoogle.com/chapter/People%20+%20AI%20Guidebook%20-%20Explainability%20+%20Trust.pdf); [QMUL copy of key considerations](https://qmplus.qmul.ac.uk/mod/resource/view.php?id=2731783). A systematic review notes PAIR is the main industrial guideline that addresses trust *calibration* specifically — [arXiv 2311.06305](https://arxiv.org/pdf/2311.06305).
- PAIR "Errors + Graceful Failure": whether something is an "error" depends on user expectations (a recommender useful 60% of the time can be a success or failure depending on purpose); creating paths for users to act on errors "encourages patience with the system" and keeps the relationship going; worksheet includes an "error audit" exercise — [PAIR Errors + Graceful Failure PDF](https://pair.withgoogle.com/chapter/People%20+%20AI%20Guidebook%20-%20Errors%20+%20Graceful%20Failure.pdf); [PAIR worksheet](https://pair.withgoogle.com/worksheet/errors-failure.pdf).
- Apple publishes a "Human Interface Guidelines: Generative AI" page (listed as a resource for WWDC25 session 248 on prompt design & safety for on-device foundation models); Apple ML Research describes new Generative AI HIG tied to its Responsible AI principles — [WWDC25 session 248](https://developer.apple.com/videos/play/wwdc2025/248/); [Apple ML Research, 2025 foundation model updates](https://machinelearning.apple.com/research/apple-foundation-models-2025-updates). (Exact HIG wording not retrieved — see Gaps.)

**Generative UI (UI generated on the fly)**
- Google Research (18 Nov 2025) introduced a generative UI implementation built on Gemini 3 Pro that produces full interactive experiences per prompt; interfaces were "strongly preferred by human raters over standard LLM outputs" when generation speed is ignored; shipped as "dynamic view" and "visual layout" experiments in the Gemini app and in Google Search AI Mode — [Google Research blog](https://research.google/blog/generative-ui-a-rich-custom-visual-interactive-user-experience-for-any-prompt/); [9to5Google Gemini 3 launch](https://9to5google.com/2025/11/18/gemini-3-launch/). Accompanying paper reportedly titled "Generative UI: LLMs are Effective UI Generators" (title from a secondary source) — [eDiscovery Today](https://ediscoverytoday.com/2025/11/19/generative-ui-a-new-ai-driven-user-experience-paradigm-from-google-artificial-intelligence-trends/).
- Vercel AI SDK: generative UI = model calls a tool → tool returns data → data is rendered by a React component. In AI SDK 5, tool calls appear in `message.parts` with typed names `tool-${toolName}` and states `input-available` (show loading), `output-available` (render component), `output-error` (show error) — [AI SDK docs: Generative User Interfaces](https://ai-sdk.dev/docs/ai-sdk-ui/generative-user-interfaces); [v5 docs](https://ai-sdk.dev/v5/docs/ai-sdk-ui/generative-user-interfaces). The older RSC `streamUI` approach (AI SDK 3.0, 2024) is paused — [Vercel blog AI SDK 3](https://vercel.com/blog/ai-sdk-3-generative-ui); [rsc-genui template](https://blog.vercel.com/templates/ai/rsc-genui).
- Agent-UI protocol stack (2025–2026): **A2UI** is declarative — the agent emits JSON referencing a client-owned component catalogue, the client renders natively (v0.9.1 production, v1.0 candidate); **AG-UI** is the event/state transport between agent backend and frontend; **MCP Apps** ship prebuilt web UI that the host sandboxes in an iframe and talks to via JSON-RPC over postMessage — [A2UI ecosystem page](https://a2ui.org/introduction/agent-ui-ecosystem/); [AG-UI docs](https://docs.ag-ui.com/introduction); [sunpeak: MCP Apps vs A2UI (Oct 2026)](https://sunpeak.ai/blogs/mcp-apps-vs-a2ui/); [CopilotKit generative-ui examples repo](https://github.com/CopilotKit/generative-ui).
- Intent/outcome-oriented design: secondary summaries of NN/g describe generative AI as the third UI paradigm ("intent-based outcome specification" — users state the result, system works out steps) and "outcome-oriented design" where designers set goals/guardrails rather than fixed layouts; suggested metrics shift to completion rate per *intent* and "override rate" (how often users abandon the generated path) — [Capicua](https://www.capicua.com/blog/generative-ui-genui-strategy); [Foolproof](https://foolproof.co.uk/journal/what-is-gen-ui-and-does-it-matter). (NN/g original not retrievable here.)

**Editable plans, "show your work" timelines, HITL approvals, undo**
- Gemini Deep Research drafts a research plan and offers **Edit plan** before any browsing starts (refine scope, add/remove sub-questions), then **Start research**; reports typically take ~5–10 minutes — [New School KB](https://services.newschool.edu/TDClient/32/Portal/KB/Article/1365/How-to-use-Deep-Research-in-Google-Gemini); [ai-toolbox guide](https://www.ai-toolbox.co/gemini-management-and-productivity/how-to-use-gemini-deep-research-2026).
- ChatGPT agent (2025) offered pause/interrupt/take-over-browser controls, a running narration log, explicit confirmation before high-impact actions (emails, purchases), required browser takeover for credentials, and a "watch mode" requiring supervision on certain sites; OpenAI's help page now states ChatGPT agent "is no longer available" and points to "ChatGPT Work" — [OpenAI Help: ChatGPT agent](https://help-lb.openai.com/en/articles/11752874-chatgpt-agent); [Kommunicate guide](https://www.kommunicate.io/blog/chatgpt-agent-mode/); [Chatbase guide](https://chatbase.co/blog/chatgpt-agent-mode).
- Undo for AI actions: Cursor "checkpoints" are automatic local snapshots of Agent edits restorable from a message (not version control; agent changes only); Claude Code `/rewind` rolls back conversation and file changes to an earlier checkpoint — [Cursor docs: Checkpoints](https://docs.cursor.com/agent/chat/checkpoints); [MindStudio on /rewind](https://www.mindstudio.ai/blog/claude-code-rewind-command-rollback). A Cursor forum thread reports a bug where chat looks reverted but files stay modified — "real undo paths matter more than cosmetic ones" — [Cursor forum](https://forum.cursor.com/t/chat-checkpoints-dont-revert-code-properly/152855); [ProCreator](https://procreator.design/blog/best-ux-tips-when-designing-for-ai-agents).
- Practitioner guidance (2026): HITL checkpoint = a visible gate where a person reviews the *exact* action before it becomes irreversible; keep a separate activity log with per-action reverse; risk-tiered gates (pause before email, spending, destructive file ops) — [AI UX Playground HITL guide](https://aiuxplayground.com/guides/how-to-design-human-in-the-loop); [Towards AI, 8 agent UX patterns](https://pub.towardsai.net/designing-for-ai-agents-8-ux-patterns-that-build-trust-in-2026-713a0c926933); [AgenticWire checklist](https://www.agenticwire.news/article/agent-ux-design-patterns).
- Approval fatigue: binary approve/reject on every step produces rubber-stamping; recommend approving permission scopes/constrained intents instead (vendor blog; cited study figure unverified) — [Kunal Ganglani](https://www.kunalganglani.com/blog/tool-approval-patterns-ai-agents).
- Graduated autonomy: a 2025 University of Washington framework (Knight First Amendment Institute) defines five user roles from Operator to Observer, with Approver in between; KPMG reportedly found 63% of companies require human validation of agent outputs, up from 22% (both via secondary source) — [21TORR](https://www.21torr.com/en/blog/artikel/from-ux-to-ax-agentic-ux-design-shift).

**Confidence / uncertainty / explainability / citations**
- Kim, Liao, Vorvoreanu, Ballard & Vaughan (FAccT 2024), pre-registered experiment, n=404, medical Q&A with a fictional LLM search engine: first-person hedges ("I'm not sure, but…") lowered agreement with the system and *increased* participant accuracy by reducing (not eliminating) over-reliance on wrong answers; impersonal "It's not clear, but…" had weaker, non-significant effects — wording matters — [Microsoft Research](https://www.microsoft.com/en-us/research/?p=1030965); [arXiv 2405.00623](https://www.arxiv.org/abs/2405.00623).
- NN/g "Explainable AI in Chat Interfaces": confident-sounding answers earn undeserved trust; AI citations are often hallucinated or point to unrelated sources; people rarely click citation links, so the appearance of sourcing inflates confidence; model "explanations" are often unfaithful to actual computation — [NN/g](https://www.nngroup.com/articles/explainable-ai/).
- NN/g: users are more likely to follow AI advice when they perceive it as smart rather than emotional — [NN/g, Prioritize Smarts over Sentience](https://www.nngroup.com/articles/smarts-emotion-trust-ai/).
- Citation UX in production: Perplexity uses domain chips, visible research steps, a Links tab, "Check sources" on selection and "Wrong sources" feedback; ChatGPT uses publisher chips on claims, claim-anchored popovers with 1/N paging and a Sources sidebar (teardown, July 2026) — [AI UX Playground teardowns](https://aiuxplayground.com/teardowns/compare/trust-privacy-settings).
- NN/g State of UX 2026 frames 2025 as "post-hype AI": real use cases (coding, search agents) but continued inconsistency, hallucinations, edge-case failures and need for human oversight; NN/g's 2025 research agenda suggests interfaces may need to serve both people and agents acting for them — [NN/g State of UX 2026](https://www.nngroup.com/articles/state-of-ux-2026/); [NN/g GenAI UX research agenda](https://www.nngroup.com/articles/genai-ux-research-agenda/); [NN/g service design & AI agents (Feb 2025)](https://www.nngroup.com/articles/service-design-evolve-ai-agents/).
- Regulatory driver: EU AI Act Article 50 transparency obligations apply from 2 Aug 2026 — chatbots must inform people they are interacting with AI unless obvious; synthetic content must be machine-detectable (possible delay to 2 Dec 2026 for systems already on market, per Digital Omnibus provisional agreement — sources differ); fines up to €15M or 3% of turnover — [Cooley](https://www.cooley.com/news/insight/2026/2026-08-03-eu-ai-act-transparency-obligations-take-effect-2-august-2026); [Sidley Data Matters](https://datamatters.sidley.com/2026/06/24/eu-ai-act-transparency-obligations-preparing-for-compliance-by-2-august-2026/).

### Inferences
Pattern cards (what / who / why / prototype / a11y). Prototyping notes are my recommendations, not sourced facts.

1. **Generative UI cards ("answer as an interface")** — *Who:* Gemini dynamic view, Google AI Mode, v0, AI SDK apps. *Why:* raters strongly preferred generated interfaces over text (Google). *Prototype:* Next.js + AI SDK `useChat`; define 3–5 tools (e.g., `showComparisonTable`, `showMap`, `showChecklist`) and render each `tool-*` part state (skeleton → component → error). Figma: build a component catalogue and storyboard a prompt → card transformation. Constrain to a *fixed catalogue* (A2UI philosophy) so output stays on-brand and accessible. *A11y:* generated components must still have semantic roles, focus management when a card appears (move focus or announce via `aria-live="polite"`), and a text fallback.
2. **Editable plan before execution ("plan card")** — *Who:* Gemini Deep Research, coding agents. *Why:* HAX G9 (efficient correction) and HITL guidance; cheaper to fix a plan than a result. *Prototype:* LLM returns JSON steps → render as a reorderable, checkable list with inline edit, "Add step", and a primary "Run plan" button. *A11y:* reorder via keyboard (up/down buttons, not drag-only); announce changes.
3. **"Show your work" agent timeline + activity log with per-step undo** — *Who:* ChatGPT agent (narration), Perplexity research steps, Cursor/Claude Code checkpoints. *Why:* visibility of system status + real reversibility. *Prototype:* vertical timeline (step, status icon, timestamp, "view details", "undo this step"); keep state in an array of snapshots so undo truly restores. *A11y:* timeline as an ordered list; status not by colour alone; `aria-live` for new steps but throttled to avoid chatter.
4. **Risk-tiered approval gate** — low-risk actions auto-run; medium show a dismissible toast with undo; high-risk (money, sending, deleting) show an exact-action preview ("Send this email to 3 recipients: …") with Approve/Edit/Cancel. Avoid approval fatigue by approving scopes ("allow this agent to edit my calendar this week").
5. **Calibrated uncertainty** — use first-person verbal hedges for low-confidence answers (evidence: Kim et al. 2024), highlight unverified claims, and show "how sure" in *words matching precision* (HAX 2A/2B) rather than fake-precise percentages. Pair with a "verify" affordance (claim-anchored source popover) because people don't click generic citation lists (NN/g).
6. **Claim-anchored citations + "wrong source" feedback** — popover per claim with quote snippet; one-tap "this source doesn't support this" feeding back into the UI.
7. **Graceful AI failure** — explicit "I couldn't do X because Y; here's what you can do" with 2–3 recovery chips (rephrase, narrow scope, do manually) per PAIR's "paths forward".
8. **AI identifier + disclosure label** — consistent sparkle/colour/name for AI-generated content (Shape of AI "Identifiers"), which also aligns with EU AI Act Art. 50 in 2026 — a timely talking point for judges.

### Gaps
- Could not retrieve the full text of NN/g's generative-UI/outcome-oriented-design article, Apple's HIG Generative AI page, or the current shapeof.ai pattern pages (egress-blocked); details above come from search extracts and secondary summaries.

## 2. Adaptive & personalized interfaces (expertise, context, ability, cognitive load, calm technology, progressive disclosure)

### Takeaway
The most credible, hackathon-friendly adaptivity in 2025–2026 is *preference- and context-driven* (OS accessibility settings via CSS media queries, data-saver/offline states, a user-chosen "focus/calm" mode, expertise toggles) rather than opaque ML-driven layout changes; "calm technology" now has a formal certification (Calm Tech Institute, 81-point standard) that gives teams a citable rubric.

### Cited Findings
- `prefers-reduced-motion: reduce` signals the user wants minimal motion; it does not mean all animation must be removed — disable non-essential motion — [MDN: Using media queries for accessibility](https://developer.mozilla.org/en-US/docs/Web/CSS/Media_Queries/Using_media_queries_for_accessibility).
- `prefers-contrast` can provide a high-contrast version that reduces barriers for visually impaired visitors; `prefers-reduced-data` exists in Media Queries Level 5 but had no browser support per the (dated) source; Level 5 user-preference features are still working draft — [Sustainable Web Design guideline 3.12](https://sustainablewebdesign.org/guidelines/3-12-use-sustainability-beneficial-user-preference-media-queries/); [InfoQ](https://infoq.com/news/2020/06/responsive-design-media-queries).
- Apple Liquid Glass automatically responds to Reduce Transparency, Increase Contrast and Reduce Motion system settings without developer work — an example of OS-level adaptive presentation — [Infinum](https://infinum.com/blog/apples-ios-26-liquid-glass-sleek-shiny-and-questionably-accessible/).
- Calm Tech Institute (founded May 2024 by Amber Case) certifies products against an 81-point standard across six categories: attention, periphery, durability, light, sound, materials; asks that all but the "most crucial" notifications be off by default; certified examples include reMarkable Paper Pro, Daylight Computer, Airthings View Plus, Mui Board Gen 2 (CES 2025), and Mudita Kompakt/Harmony 2/Bell 2 (Platinum, Oct 2025) — [IEEE Spectrum](https://spectrum.ieee.org/calm-tech); [Slashdot/IEEE](https://tech.slashdot.org/story/25/01/22/056208/calm-tech-certification-rewards-less-distracting-tech); [Mudita PR](https://www.streetinsider.com/PRNewswire/Mudita+Products+Recognized+by+Calm+Tech+Institute/25422419.html); [Calm technology – Wikipedia](https://en.wikipedia.org/wiki/Calm_technology).
- Neurodiversity guidance commonly recommends a single "calm"/"focus" mode that hides non-essential elements plus adjustable font, colour and contrast — [Smashing Magazine, Designing for Neurodiversity (Jun 2025)](https://www.smashingmagazine.com/2025/06/designing-for-neurodiversity/); [accessiBe](https://accessibe.com/blog/knowledgebase/how-to-design-digital-environments-for-people-with-neuro-divergency).
- W3C COGA "Making Content Usable" lists "adaptation and personalization" as one of its eight objectives — [W3C COGA (TR)](https://www.w3.org/TR/coga-usable); [Deque axe-con slides](https://www.deque.com/axe-con/wp-content/uploads/2021/12/axe-con-2022-COGA-Content-Usable.pdf).
- A 2025 paper proposes adaptive, cognitive-load-managing AI interfaces for ADHD/autistic users, arguing one-size-fits-all models fail them — [ResearchGate: Adaptive UX Frameworks for Neurodivergent Users](https://www.researchgate.net/publication/393905078_Adaptive_UX_Frameworks_for_Neurodivergent_Users_Integrating_Cognitive_Load_Management_into_AI-Driven_Interfaces).
- Hick's Law: decision time rises with number/complexity of choices — a core rationale for progressive disclosure — [Laws of UX](https://lawsofux.com/index.md).
- GOV.UK: start with one question/decision per page; helps comprehension, mobile use, error recovery and enables auto-save and branching (progressive disclosure for forms) — [GOV.UK Service Manual: Form structure](https://www.gov.uk/service-manual/design/form-structure).
- Lite/low-bandwidth variants as context adaptation: Pinterest Lite PWA ~1.4 MB vs 143 MB iOS app; Twitter Lite under 1 MB and fast on 3G — [TechCrunch](https://techcrunch.com/2019/10/09/pinterest-launches-a-lite-app-for-emerging-markets/amp/); [Think with Google PWA guide](https://www.thinkwithgoogle.com/_qs/documents/1964/1008-Progressive-Web-Apps.pdf).

### Inferences
1. **"Adapt to me" panel (user-controlled personalization)** — one sheet with toggles: Focus mode, Reduce motion, High contrast, Larger text, Dyslexia-friendly spacing, Simple language, Data saver. Default each toggle from OS media queries, then let users override; persist in localStorage. Highly demo-able: flip one switch on camera and the whole UI transforms. *A11y:* the panel itself must be reachable in ≤2 taps from every screen and keyboard-operable.
2. **Expertise dial (Beginner ↔ Pro)** — beginner view shows guided steps and explanations; pro view reveals keyboard shortcuts, dense tables, command palette. Prototype as a CSS class on `<body>` that shows/hides `[data-level]` elements. Avoid auto-switching by inference (unpredictable for autistic users per predictability guidance in §3).
3. **Context-aware states** — `navigator.onLine` + `online/offline` events → banner "You're offline; changes will sync"; time-of-day greeting/dark theme suggestion; reduce image quality under data saver. Keep adaptations *announced and reversible* (calm tech: periphery, not interruption).
4. **Calm notifications by default** — notifications off except critical; daily digest instead of pings; cite Calm Tech 81-point standard in the pitch as a design rubric.
5. **Cognitive-load meter (demo trick)** — show "3 decisions on this screen" vs "11 before" as a Hick's-Law-inspired before/after metric (inference; not a standard metric).

### Gaps
- No rigorous 2025–2026 evidence found on ML-driven adaptive layouts improving outcomes; most adaptivity evidence is guidance-level.
- Current browser support for `prefers-reduced-data` and the `Save-Data` client hint was not confirmed by sources retrieved (the source saying "no support" is dated).
- No Calm Tech Institute data on measured user outcomes (it is a certification rubric, not an outcome study).

## 3. Inclusive design frontiers (neurodiversity, COGA, low-literacy/vernacular, voice-first & multimodal, older adults, situational disabilities, one-hand mode, Easy Read)

### Takeaway
Inclusive features that are *visible on camera* — voice-first vernacular input, an Easy Read/simple-language toggle, a focus mode, thumb-reachable one-hand layouts, and "I don't know" answer options — are both evidence-backed and differentiating; but avoid folk remedies (e.g., OpenDyslexic shows no reading-speed/accuracy benefit in the best controlled study).

### Cited Findings
**Cognitive accessibility (W3C COGA)**
- W3C "Making Content Usable for People with Cognitive and Learning Disabilities" is a Working Group Note (first published April 2021), supplemental to WCAG 2.2 and not required for conformance; organized into eight objectives: help users understand what things are and how to use them; find what they need; use clear content; avoid and correct mistakes; help users focus; ensure processes do not rely on memory; provide help and support; support adaptation and personalization — each with design patterns (rationale, how-to, examples) — [W3C TR](https://www.w3.org/TR/coga-usable); [W3C editor's draft](https://w3c.github.io/coga/content-usable/); [Deque axe-con 2022 slides](https://www.deque.com/axe-con/wp-content/uploads/2021/12/axe-con-2022-COGA-Content-Usable.pdf).

**Neurodiversity (ADHD, dyslexia, autism)**
- Smashing Magazine (June 2025) "Designing For Neurodiversity" — [Smashing](https://www.smashingmagazine.com/2025/06/designing-for-neurodiversity/). Stéphanie Walter's Neurodiversity & UX toolkit gives practical guidance for dyslexia, dyscalculia, autism and ADHD — [accessibilitychecker.org summary](https://www.accessibilitychecker.org/blog/neurodivergent-ux-design/).
- Common recommendations: ADHD — minimise auto-play and pop-ups, break long forms into step-by-step wizards; autism — predictable layouts and literal CTAs (vague CTAs create anxiety); dyslexia — familiar sans-serif fonts, line-height ≥1.5, ~80-character line length; customisation and "calm/focus" modes (blog-level consensus, not independently validated) — [Adchitects](https://adchitects.co/blog/design-for-neurodiversity); [accessiBe](https://accessibe.com/blog/knowledgebase/how-to-design-digital-environments-for-people-with-neuro-divergency); [Bitskingdom](https://bitskingdom.com/blog/inclusive-design-neurodivergent-users/).
- GAIA guide: 28 recommendations for autism-accessible interfaces (simple language, predictable navigation, clear feedback, removing distractions, customisation, redundant representations), used by the 2025 WING literacy platform — [arXiv WING 2512.16067](https://arxiv.org/pdf/2512.16067).
- Stakeholder research found existing autism GUI guidelines generic and heterogeneous — [PMC8123795](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC8123795/).
- OpenDyslexic: Wery & Diliberto (2016) found no improvement in reading rate or accuracy for students with dyslexia vs Arial/Times; some small/adult studies report comprehension gains but not speed — evidence small and mixed — [PMC5629233](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC5629233/); [Springer](https://link.springer.com/article/10.1007/s11881-016-0127-1).

**Low-literacy, vernacular, voice-first (India focus)**
- Hello Ujjivan banking app uses conversational Hindi voice plus large icons; AI voice apps (incl. Bhashini) target India's ~18 crore low-literate citizens — [ThePrint](https://theprint.in/ground-reports/voice-based-banking-for-low-literate-indians/2610584/).
- Bhashini powers voice-based UPI payments via a phone number (works on feature phones) in Hindi, English or Telugu; Maharashtra's MahaVISTAAR-AI farmer app uses Bhashini for multilingual conversational advisories; Bhashini is primarily an API layer, so UX is the app builder's job — [Entrepreneur India](https://india.entrepreneur.com/news-and-trends/bhashini-bridging-the-digital-literacy-gap-in-tier-2-and/479188); [Anantam IAS explainer](https://anantamias.com/bhashini-bhasha-interface-for-india/?pdf=1). Language coverage claims conflict (12 vs 22 scheduled languages) — same sources.
- A study comparing form-based myScheme with a voice-based conversational prototype (Prabodhini) with 15 low-income participants found the conversational design better aligned with "emergent users'" mental models (small sample) — [ACL Anthology author page](https://aclanthology.org/people/bhaskar-ruthvik-bikkina/unverified/).
- "Voice-first design isn't just speech-to-text on top of a text UI — it requires rethinking navigation flows, feedback mechanisms" — [ProductGrowth: Vernacular EdTech](https://productgrowth.in/insights/edtech/vernacular-edtech-bharat/).

**Situational disabilities & one-hand use**
- Microsoft Inclusive Design "persona spectrum": permanent (one arm), temporary (arm in a cast), situational (holding a child); solutions for permanent cases extend to many — [CareerFoundry](https://careerfoundry.com/en/blog/ux-design/persona-spectrums/). Critique: the framework is overused and can understate real access barriers — [Experience Dynamics](https://dev.experiencedynamics.com/?p=26225).
- Steven Hoober's 1,333 field observations (2013): 49% one-handed grip, 36% cradled, 15% two hands; thumbs drive ~75% of interactions; Hoober later warned rigid "thumb zone" maps were misread — people view and touch the screen *centre* most frequently, accurately and quickly — [A List Apart](https://alistapart.com/1-2-phone-grips-jpg/); [Monterail](https://www.monterail.com/blog/thumb-friendly-navigation-word-oriented-design); [UXmatters 2013](https://www.uxmatters.com/mt/archives/2013/02/how-do-users-really-hold-mobile-devices.php?).
- Smashing: "How To Design Mobile Apps For One-Hand Usage" — [Smashing Magazine](https://smashingmagazine.com/2020/02/design-mobile-apps-one-hand-usage/).

**Older adults**
- NN/g's 2013 senior-usability article is superseded by "Usability for Older Adults: Challenges and Changes"; older adults still struggle to access essential services online — [NN/g](https://www.nngroup.com/articles/usability-seniors-improvements/); NN/g guide to testing with 65+ users — [NN/g](https://www.nngroup.com/articles/usability-testing-older-adults/).
- Content analysis of 100 senior-resource websites: font size, information organisation and colour/contrast together explained 62% of variance in accessibility — [PMC7741326](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC7741326/).
- Material 3 Expressive research reported older users performed as well as younger users on expressive designs (Google claim via press) — [Phandroid](https://phandroid.com/2025/05/13/material-3-expressive-makes-google-apps-feel-less-robotic/).

**Easy Read & plain language**
- Easy Read pairs short, simple text blocks with supporting images; for people with learning disabilities, low literacy or limited English; avoid pixelated/irrelevant/complex images; ~15–20 words per statement, one idea per block; ≤3 lines per paragraph; Australian Style Manual targets Year 4–6 reading level, bolding and defining difficult words; online Easy Read should use consistent layouts, avoid italics and not link to non-Easy-Read content; always test with people with learning disabilities — [NSW DCJ Design System: Easy Read](https://designsystem.dcj.nsw.gov.au/templates/easy-read.html); [Australian Style Manual](https://stylemanual.gov.au/node/63); [Nottinghamshire ICB toolkit](https://notts.icb.nhs.uk/wp-content/uploads/sites/2/2025/08/Easy-Read-Advice-for-Toolkit-v0.2.pdf); [Delib guidance](https://help.delib.net/article/1410-easy-read-guidance).
- Scottish Government design system: allow "I do not know / not sure" as valid answers where appropriate — [designsystem.gov.scot question page](https://designsystem.gov.scot/patterns/question-page).

### Inferences
1. **Voice-first vernacular mode** — mic button as primary CTA with spoken confirmation and large-icon fallback; demo in Hindi/regional language (Bhashini APIs or browser Web Speech API for a prototype). *A11y:* always provide a visible text transcript and a non-voice path (speech impairment, noisy environments).
2. **"Explain simply" / Easy Read toggle** — one tap rewrites the screen's copy to short, one-idea sentences with icons (LLM-assisted, then human-reviewed). Strong judge moment: same screen, two literacy levels.
3. **Focus mode for ADHD** — hides secondary nav, timers, badges; shows one task + progress; supports "pause and resume later" (COGA: don't rely on memory).
4. **Predictability guarantees for autistic users** — literal button labels ("Pay ₹499 now" not "Continue"), no surprise layout shifts, preview of what happens next.
5. **One-hand / reach mode** — bottom-anchored primary actions, bottom sheets instead of top menus, large targets; per Hoober, keep key content central rather than slavishly following thumb-zone heatmaps.
6. **Senior-friendly defaults** — larger base font, high contrast, explicit labels with icons, generous targets; easy to show via the "Adapt to me" panel.
7. **Don't ship OpenDyslexic as "the dyslexia fix"** — offer spacing/line-length controls instead; judges with accessibility knowledge may notice.

## 4. Trust & ethics UX (dark-pattern avoidance — India CCPA 2023, EU DSA; privacy-respecting consent; transparent pricing; "anti-dark-patterns" as a feature)

### Takeaway
Dark-pattern regulation tightened sharply in 2023–2026 (India's 13-pattern CCPA guidelines plus a June 2025 self-audit mandate; India's DPDP Rules notified Nov 2025; EU DSA Art. 25 and a forthcoming Digital Fairness Act; FTC's $2.5B Amazon Prime settlement), so a hackathon product that visibly *audits itself* against these lists — symmetric consent, one-tap cancel, all-in pricing, no fake urgency — turns compliance into a differentiating, judge-friendly feature.

### Cited Findings
**India**
- India's Central Consumer Protection Authority (CCPA) notified the Guidelines for Prevention and Regulation of Dark Patterns, 2023 on 30 Nov 2023 under Section 18 of the Consumer Protection Act, 2019; Annexure 1 lists 13 patterns: false urgency, basket sneaking, confirmshaming, forced action, subscription trap, interface interference, bait and switch, drip pricing, disguised advertisement, nagging, trick questions, SaaS billing, rogue malware (up from 10 in the Sept 2023 draft) — [KS&K](https://ksandk.com/newsletter/safeguarding-consumer-rights-dark-patterns-guidelines-2023/); [Mondaq overview](https://www.mondaq.com/ccpas-guidelines-on-dark-patterns-an-overview/1844140); [JSA](https://www.jsalaw.com/newsletters-and-updates/ccpa-issues-guidelines-for-prevention-and-regulation-of-dark-patterns-2023/); [Draft guidelines PDF](https://consumeraffairs.nic.in/sites/default/files/file-uploads/latestnews/Draft%20Guidelines%20for%20Prevention%20and%20Regulation%20of%20Dark%20Patterns%202023.pdf).
- Examples: basket sneaking = pre-checked add-ons/donations at checkout without consent; subscription trap = hard-to-find cancellation or free trials demanding payment details; trick questions = double negatives — [KS&K](https://ksandk.com/newsletter/safeguarding-consumer-rights-dark-patterns-guidelines-2023/); [Mondaq](https://www.mondaq.com/ccpas-guidelines-on-dark-patterns-an-overview/1844140). Illustrations are guidance, not binding interpretation; no independent penalty specified — [Cyril Amarchand blog](https://corporate.cyrilamarchandblogs.com/2023/12/dark-pattern-guidelines-illuminating-or-illusory/).
- CCPA advisory of 5 June 2025 directed e-commerce platforms to self-audit for dark patterns within three months and submit self-declarations; references Rule 4(9) of the Consumer Protection (E-Commerce) Rules, 2020 (explicit, affirmative consent for purchases) — [AZB & Partners](https://www.azbpartners.com/bank/central-consumer-protection-authority-issues-advisory-to-e-commerce-platforms-for-self-audit-to-detect-dark-patterns-on-their-platforms/); [Storyboard18](https://www.storyboard18.com/digital/ccpa-warns-e-comm-firms-over-dark-patterns-self-audit-within-3-months-69249.htm); [IndiaLaw](https://www.indialaw.in/blog/civil/ccpas-dark-patterns-mandates-self-audit/).
- India DPDP Rules 2025 (notified Nov 2025): notices must be clear, standalone, plain-language, list data, purposes, contact and withdrawal routes; withdrawal must be as easy as giving consent; consent managers must offer an accessible, transparent, interoperable platform to give/manage/review/withdraw consent and keep records 7 years; staggered commencement (reported Nov 13 2026 for consent-manager rule; May 13 2027 for notice rules — estimates) — [SCC Online](https://www.scconline.com/blog/post/2025/12/26/digital-personal-data-protection-rules-2025-key-highlights/); [Mondaq](https://www.mondaq.com/india/data-protection/1708164/digital-personal-data-protection-rules-2025-notified); [Tsaaro](https://tsaaro.com/blogs/dpdp-rules-2025-explained-full-overview-and-practical-summary).

**EU / US**
- EU DSA Article 25 prohibits manipulative interface design by online platforms, but its scope is limited by a carve-out referring to the Unfair Commercial Practices Directive; the Commission and Ireland's Coimisiún na Meán have examined notice-and-action designs under Art. 25(1) — [Univ. Parthenope](https://ricerca.uniparthenope.it/handle/11367/162158); [A&L Goodbody](https://www.algoodbody.com/insights-publications/digital-fairness-act-a-necessary-safeguard-or-unnecessary-duplication).
- EU Digital Fairness Act: expected to target dark patterns, addictive design and influencer marketing; Commission floated a "fairness-by-design" obligation; timing conflicts (Q3 2026 adoption per 2025 source vs Q4 2026 proposal per May 2026 source; no draft published as of that article) — [Taylor Wessing](https://www.taylorwessing.com/de/interface/2025/the-dmcca/eu-consumer-law-reform-is-coming-but-when-will-it-happen-and-what-will-it-cover); [Heuking (May 2026)](https://www.heuking.de/en/news-events/newsletter-articles/detail/digital-fairness-act-implementation-obligations-companies-need-to-prepare-for.html).
- FTC/ICPEN/GPEN sweep (10 July 2024): >75% of subscription sites used ≥1 dark pattern and >65% used ≥2; ~97% of sites/apps in GPEN's privacy review used dark patterns; sneaking (no way to turn off auto-renewal at sign-up) was most common — [Baker McKenzie/BakerLaw](https://www.bakerlaw.com/insights/dark-patterns-go-international-ftc-and-international-consumer-protection-networks-conduct-sweep-of-deceptive-design-practices-related-to-subscription-services-privacy); [Hunton](https://huntonak.com/privacy-and-information-security-law/ftc-and-consumer-protection-networks-review-use-of-dark-patterns).
- FTC secured a record $2.5B settlement with Amazon (Sept 2025) over Prime sign-up/cancellation dark patterns, including a clear decline button and a third-party monitor — [Ohio State DESIS summary](https://desis.osu.edu/seniorthesis/?p=18643) (secondary).
- Harry Brignull coined "dark patterns" in 2010; catalogue at deceptive.design — [NBC News](https://www.nbcnews.com/news/dark-patterns-regulators-eye-tech-tricks-hurt-consumers-rcna4365).
- FTC rule requiring all-in (fee-inclusive) up-front pricing for live-event ticketing and short-term lodging; FTC says it bans no specific fee but requires total price disclosure — [WJLA](https://wjla.com/news/offbeat/federal-regulators-unveil-final-junk-fees-rule-for-live-events-hotels-ftc-trade-commission-lina-khan-las-vegas-resorts-southern-nevada).

**Consent UX evidence**
- Nouwens et al. (CHI 2020): only 12.6% of scraped consent banners showed accept and reject on the same page; removing "reject" from the first layer raised consent by ~22–23 percentage points; unequal prominence is considered non-compliant with GDPR — [arXiv 2001.02479](https://arxiv.org/pdf/2001.02479).
- Politecnico di Torino CMP study (400+ sites, 4M+ interactions): only 1–4% opt out when >1 click is needed; with a single-click "Reject all", denial rose to ~21% — [IRIS PoliTo](https://iris.polito.it/handle/11583/2981764).

### Inferences
1. **"Fairness receipt" / dark-pattern self-audit badge** — an in-product panel listing the CCPA's 13 patterns with a ✓ and a one-line "how we avoid it" (e.g., "No pre-ticked add-ons", "Cancel in 1 tap", "Price shown is final"). Directly mirrors the June 2025 CCPA self-audit/self-declaration requirement — a very strong India-context story.
2. **Symmetric consent** — Accept/Reject equal size & colour on first layer, plain-language purpose cards, per-purpose toggles, and a "withdraw as easy as giving" control in settings (DPDP Rules). Show a consent *history* timeline (inspired by consent-manager record-keeping).
3. **All-in price from first view** — show total incl. fees/taxes on listing cards; checkout itemization with no surprises; a "price lock" note. Counter-demo: show a mocked "drip pricing" flow vs. yours.
4. **One-tap cancel / pause subscription** with honest retention ("Pause for a month?") but no confirmshaming copy.
5. **Honest urgency** — only show stock/timer info if real, with "why am I seeing this?" info icon.
6. **Pitch framing:** "Ethical by default" aligns with India CCPA (2023, 2025), DPDP Rules (2025), EU DSA Art. 25 / DFA, and FTC actions — judges in 2026 recognise this regulatory momentum.

- Effective date and current legal status of the FTC junk-fees rule, and the status of the FTC click-to-cancel rule (reportedly vacated in 2025 — unverified here), were not confirmed.
- No evidence found on whether visible "ethics badges" increase user trust/conversion (would be a novel claim; frame as hypothesis).

## 5. Delight & craft (micro-interactions, motion/spring physics, View Transitions API, haptics, sound, skeleton/optimistic UI, empty states, celebrations, Material 3 Expressive, Liquid Glass, bento grids, spatial UI)

### Takeaway
2025's two big visual-language shifts — Google's research-backed Material 3 Expressive (springs, shape morphing, bold emphasis; 46 studies, 18k+ participants) and Apple's Liquid Glass (translucent layered material; criticised for legibility) — make *purposeful expressive motion* the craft trend; on the web, same-document View Transitions became Baseline in Oct 2025, so smooth state-morphing is now cheap to build. Optimistic UI (Linear-style instant feedback) is the highest-impact "feel" upgrade; skeleton screens have mixed evidence.

### Cited Findings
**Material 3 Expressive (Google, May 2025)**
- Based on 46 research studies, hundreds of designs and 18,000+ participants worldwide using eye tracking, surveys, focus groups, experiments and usability testing — [Android Authority](https://www.androidauthority.com/google-material-3-expressive-details-3554486/); [Phandroid](https://phandroid.com/2025/05/13/material-3-expressive-makes-google-apps-feel-less-robotic/).
- Users spotted key UI elements up to 4× faster (Android Authority) / found tappable items 4× faster in eye-tracking (Phandroid) — outlets differ on what was measured; older users performed as well as younger ones; expressive versions rated more "energetic," "creative," "friendly"; 87% of younger users preferred the new designs (per Phandroid) — [Android Authority](https://www.androidauthority.com/google-material-3-expressive-details-3554486/); [Phandroid](https://phandroid.com/2025/05/13/material-3-expressive-makes-google-apps-feel-less-robotic/). These are Google-reported figures, not peer-reviewed.
- M3 Expressive motion uses spring physics (stiffness/damping) replacing fixed-duration easing; Jetpack Compose exposes `MotionScheme.expressive()` vs `MotionScheme.standard()`; shape morphing via `androidx.graphics.shapes` `Morph(start,end)` (community documentation; verify on m3.material.io) — [claudskills Compose graphics](https://claudskills.com/skills/compose-graphics/SKILL.md); [pub.dev material_3_expressive](https://pub.dev/documentation/material_3_expressive/1.0.8/).

**Apple Liquid Glass (WWDC, 9 June 2025)**
- Unified design language across iOS/iPadOS/macOS/watchOS/tvOS 26: translucent, refractive "material" with specular highlights that reflects underlying content and responds to touch; called the most significant iOS redesign since iOS 7 — [Macworld](https://www.macworld.com/article/2807925/meet-liquid-glass-apple-redesigns-all-its-interfaces-at-once.html); [The National](https://www.thenationalnews.com/future/technology/2025/06/09/apple-glass-wwdc-ios-26-ipad-ai/); [TechRadar](https://www.techradar.com/tech/apple-reveals-major-visual-redesign-for-ios-26-macos-26-and-more-at-wwdc-2025).
- Accessibility criticism: one agency measured contrast around 1.5:1 in places vs WCAG's 4.5:1 minimum; text fading into layered backgrounds; blur obscures tappability; Apple guidance says use the material sparingly; respects Reduce Transparency/Increase Contrast/Reduce Motion — [Infinum](https://infinum.com/blog/apples-ios-26-liquid-glass-sleek-shiny-and-questionably-accessible/); [UX Collective](https://uxdesign.cc/liquid-glass-is-beautiful-but-is-the-chemistry-missing-00b4f79ff529). iOS 26.1 beta 4 reportedly added a "Tinted" option to tone the glass down (secondary report) — [Gulf News](https://gulfnews.com/technology/companies/apple-yields-tinted-control-in-ios-261-beta-4-tones-down-liquid-glass-after-backlash-1.500315176).

**Web motion & haptics**
- Same-document View Transitions became Baseline Newly available with Firefox 144 (stable 14 Oct 2025), part of Interop 2025; cross-document view transitions shipped in Chrome in 2024 and Safari added support — [web.dev (16 Oct 2025)](https://web.dev/blog/same-document-view-transitions-are-now-baseline-newly-available); [Chrome: View transitions 2025 update](https://developer.chrome.com/blog/view-transitions-in-2025).
- Web haptics: Safari has no Vibration API; since iOS 18 a non-standard `<input type="checkbox" switch>` + label `.click()` triggers system haptics (used by the `web-haptics` library as fallback); one source claims Apple patched this in iOS 26.5 (unverified) — treat as progressive enhancement only — [Ionic issue #29942](https://github.com/ionic-team/ionic-framework/issues/29942); [azukiazusa blog](https://azukiazusa.dev/en/blog/ios-safari-web-haptics); [web-haptics browser support](https://www.mintlify.com/lochie/web-haptics/advanced/browser-support); [Bugnet](https://bugnet.io/blog/fix-web-game-vibrate-api-not-available-ios-safari).

**Perceived performance**
- Doherty Threshold: keep system response <400 ms so neither user nor computer waits (Doherty & Thadani 1982); peak-end rule: experiences are judged by their peak and end — [Laws of UX](https://lawsofux.com/index.md); [Shopify Partners](https://www.shopify.com/partners/blog/ux-laws).
- Linear's perceived speed: UI mutations apply to in-memory/local state first and sync to the server in the background over WebSocket (no spinners); server rejection reverts the local model; reads are local (third-party reverse-engineering; conflict-resolution details disputed) — [performance.dev](https://performance.dev/what-makes-linear-feel-instant); [DEV Community](https://dev.to/0xgosu/why-linear-feels-fast-local-data-small-updates-and-product-discipline-1m53); [Hungry Minds](https://hungrymindsdev.substack.com/p/why-linear-feels-so-fast-technical).
- React 19 `useOptimistic` shows the expected result while an action is pending and automatically reverts to real state when it resolves/fails (must be set inside an action; not in React 18) — [freeCodeCamp](https://www.freecodecamp.org/news/how-to-use-the-optimistic-ui-pattern-with-the-useoptimistic-hook-in-react/); [SitePoint](https://www.sitepoint.com/react-useoptimistic-production-patterns-for-instant-ui-updates/).
- Skeleton screens: Viget (2017) simulated test found skeleton group perceived the *longest* wait (2.82 s vs 2.41 s spinner vs 2.29 s blank) and fewest agreeing it "loaded quickly" (59% vs 74% spinner); other small studies suggest slow, steady skeleton motion feels shorter; evidence mixed — [Viget](https://www.viget.com/articles/a-bone-to-pick-with-skeleton-screens); [UX Collective](https://uxdesign.cc/what-you-should-know-about-skeleton-screens-a820c45a571a).

**Celebration / habit loops**
- Duolingo: letting learners equip up to two Streak Freezes raised daily active learners +0.38% (meaningful at scale; "slack" can motivate more than rigid rules); Streak Wager A/B test lifted Day-7 retention 14%; learners who reach a 7-day streak are 3.6× more likely to complete their course (correlational) — [Duolingo blog](https://blog.duolingo.com/how-duolingo-streak-builds-habit); [Duolingo engineering](https://making.duolingo.com/how-streaks-keep-duolingo-learners-committed-to-their-language-goals).

**Layout trends**
- Bento grids (rounded, varied-size card compartments) popularised by Apple product/keynote pages (~2022–2023), now widespread on SaaS feature sections; an often-cited "35% longer dwell" claim is unsourced — [StudioMeyer](https://studiomeyer.io/en/blog/bento-grid-layouts); [Mockuuups](https://mockuuups.studio/blog/post/best-bento-grid-design-examples/).

**Tools**
- Figma Config 2025 (7 May 2025) launched Figma Make (prompt-to-code prototypes), Figma Sites (publish responsive sites), Figma Draw, Figma Buzz and grid layouts — [Digidop](https://www.digidop.com/blog/figma-announces-figma-sites-and-thats-not-all); [Arch](https://wearearch.com/blog/figma-config-2025).

### Inferences
1. **Optimistic UI everywhere** — every like/save/move updates instantly with a subtle "synced ✓" tick and auto-rollback + toast on failure (`useOptimistic`). Show a side-by-side "spinner version vs ours" in the video — visceral.
2. **View Transitions for continuity** — card expands into detail page (shared-element morph) with `document.startViewTransition()` / `view-transition-name`; wrap in `@media (prefers-reduced-motion: no-preference)` and fall back to a crossfade.
3. **Spring-based micro-interactions** — use Motion (Framer Motion) springs for buttons, toggles, bottom sheets; a "squish" on press, shape-morphing FAB à la M3 Expressive. Keep durations short and purposeful; respect reduced motion.
4. **Peak-end celebration** — a tasteful success moment at task completion (confetti/sticker + summary "You saved 4 minutes") and a pleasant end state; add Duolingo-style *forgiving* streaks (streak freeze) rather than punitive ones.
5. **Glass, but legible** — if borrowing Liquid Glass aesthetics, guarantee ≥4.5:1 text contrast with a solid scrim fallback and honour `prefers-reduced-transparency`/`prefers-contrast` — and *say so in the pitch* (shows maturity vs. the backlash).
6. **Bento dashboard / landing** — fastest way to look 2025-current; use CSS Grid with semantic headings in reading order.
7. **Haptics/sound as progressive enhancement** — `navigator.vibrate` on Android; optional subtle sounds behind a toggle; never the only feedback channel.
8. **Content-shaped skeletons only for familiar layouts, plus progressive streaming** of AI responses; avoid novel skeletons given Viget's result.
9. **Empty states that teach** — illustrated empty state with one primary action and example data ("Try with sample data") — a wayfinder (Shape of AI) pattern.

## 6. Resilience UX (offline-first, low-bandwidth modes, autosave/drafts, error recovery, forgiving forms, "undo instead of confirm")

### Takeaway
"Undo instead of confirm," autosaved one-question-per-page flows, and offline-tolerant local-first state are proven patterns (Gmail Undo Send, GOV.UK, Linear, Facebook/Twitter/Pinterest Lite) that are simple to build and dramatic to demo (pull the network cable on camera; nothing breaks).

### Cited Findings
- Andy Matuschak: prefer making actions undoable over "Are you sure?" confirmation dialogs — [Matuschak notes](https://notes.andymatuschak.org/zXH4ASvHNz488hCNgrBjQJK).
- Gmail Undo Send delays dispatch (5/10/20/30 s, default 5) rather than recalling, so undo always works; critique: a 5-second snackbar can add time pressure; Buttondown added undo-send up to two minutes alongside its confirmation step — [UX Collective](https://uxdesign.cc/an-underrated-ux-gmails-undo-send-d2a1ff04251f); [Buttondown](https://buttondown.com/blog/2020-12-16-undo-send).
- GOV.UK "one thing per page" helps low-confidence users, handles errors, branches, loops and saved progress better, and lets services save answers as users go — [GOV.UK design notes (2015)](https://designnotes.blog.gov.uk/2015/07/03/one-thing-per-page/); [GOV.UK Service Manual](https://www.gov.uk/service-manual/design/form-structure). Caveat: for long forms without a progress indicator, "click Next fatigue" — [SA.gov.au forms platform](https://www.sa.gov.au/forms-platform/creating-forms).
- Allow "I do not know"/"not sure" answers where valid — [Scottish Government design system](https://designsystem.gov.scot/patterns/question-page).
- Local-first: Linear reads locally, mutates immediately, reconciles in background, reverts on server rejection — [DEV Community](https://dev.to/0xgosu/why-linear-feels-fast-local-data-small-updates-and-product-discipline-1m53); [performance.dev](https://performance.dev/what-makes-linear-feel-instant).
- Lite apps: Facebook Lite lets users compose posts/messages during disconnections and sync later (data-saving claims are from a promotional piece); PWAs first gained traction in emerging markets for lower data use and offline operation; Twitter Lite <1 MB, near-instant repeat loads on flaky connections — [Washingtonian (promotional)](https://views.washingtonian.com/vie/how-facebook-lite-is-redefining-social-connectivity-in-emerging-markets); [Think with Google](https://www.thinkwithgoogle.com/_qs/documents/1964/1008-Progressive-Web-Apps.pdf); [DEV: lightweight apps for emerging markets](https://dev.to/abhayit2000/lightweight-mobile-apps-building-for-emerging-markets-with-low-bandwidth-and-limited-storage-445m).
- Agent-era resilience: real, tested undo for AI actions (Cursor checkpoints, Claude Code `/rewind`) — see §1 — [Cursor docs](https://docs.cursor.com/agent/chat/checkpoints).
- W3C COGA objectives include "help users avoid and correct mistakes" and "ensure processes do not rely on memory" — [Deque axe-con slides](https://www.deque.com/axe-con/wp-content/uploads/2021/12/axe-con-2022-COGA-Content-Usable.pdf).

### Inferences
1. **Undo toast instead of confirm modal** for deletes/archives/sends — soft-delete + 10 s undo + "Recently deleted" bin; configurable window (fixes Gmail's time-pressure critique). *A11y:* toast must be keyboard-reachable, announced via `role="status"`, and not auto-dismiss while focused (WCAG timing).
2. **Autosave + draft restore** — "Saved · 2 s ago" indicator; on return, "Continue where you left off?" banner (COGA: don't rely on memory).
3. **Offline-first demo** — service worker (Workbox) caches shell; IndexedDB queue for writes; offline banner; sync badge counts pending changes; replay on reconnect. Film toggling airplane mode.
4. **Forgiving inputs** — accept "12/3/26", "12 Mar", "tomorrow"; phone numbers with spaces/dashes; auto-correct obvious email typos ("gmial.com → gmail.com?"); inline, specific error messages next to fields; never clear entered data on error.
5. **Low-bandwidth mode** — text-first, images on tap, compressed thumbnails; show data-saved counter (great demo metric).
6. **Error states with recovery chips** (Retry · Save offline · Contact) rather than dead-ends.

### Gaps
- No 2025–2026 quantitative study found on undo-vs-confirm error rates; evidence is principle-level plus Gmail case.
- GOV.UK "forgiving format" pattern text not retrieved.
- No current independent data on Facebook Lite data savings.

## 7. Measurable UX (instrumenting and showing UX impact in a demo: task time, steps reduced, SUS, before/after)

### Takeaway
Judges reward evidence: a tiny before/after usability test (5–8 participants) reporting task time, steps/clicks, error count, SEQ per task and an overall SUS score (benchmark average = 68; ~80+ = top tier), framed with Google's HEART/Goals-Signals-Metrics, turns "nice UI" into a quantified claim — and AI features add intent-level metrics (completion per intent, override rate).

### Cited Findings
- SUS average ≈ 68 (50th percentile, roughly a "C"); Sauro & Lewis curved grading scale built from 241 industrial studies, with top/bottom 15 percentile points as A/F — [Lewis 2018, Journal of Usability Studies](https://uxpajournal.org/wp-content/uploads/sites/7/pdf/JUS_Lewis_May2018.pdf); [Lyssna (Sep 2025)](https://lyssna.com/blog/system-usability-scale). Another guide citing 5,000+ scores says >80.3 is top 10% and <51 bottom 15% (cut-points vary by dataset) — [Koji SUS guide](https://www.koji.so/docs/system-usability-scale-guide). A SUS of 68 is not "68 percent" of anything — [Ballpark](https://ballparkhq.com/research-glossary/system-usability-scale).
- Single Ease Question (SEQ): 7-point post-task ease rating (Sauro) — [Poper template](https://www.poper.ai/templates/surveys/usability-test-survey/); [MeasuringU SUS items](https://measuringu.com/sus-items/).
- Google HEART (Rodden, Hutchinson & Fu, CHI 2010): Happiness, Engagement, Adoption, Retention, Task success, applied via Goals → Signals → Metrics; start with 2–3 relevant categories; combine quantitative and qualitative data; engagement can mislead for mandatory tools — [IxDF](https://ixdf.org/literature/article/google-s-heart-framework-for-measuring-ux); [Product Compass](https://www.productcompass.pm/p/the-google-heart-framework); [Lyssna (Mar 2026)](https://www.lyssna.com/blog/google-heart-framework/).
- For generative/AI UIs, suggested metrics: task completion per intent class, refusal rate, override rate (users abandoning the generated path) — [Capicua](https://www.capicua.com/blog/generative-ui-genui-strategy).
- HAX pattern 2C "Report system performance information" (show users how well the AI performs) — [Microsoft HAX Toolkit](https://www.microsoft.com/en-us/haxtoolkit/library/pattern/).
- Doherty threshold (<400 ms) as a response-time target — [Laws of UX](https://lawsofux.com/index.md).
- Example of company-reported impact metrics to emulate in framing: Duolingo's A/B-tested +0.38% DAU (Streak Freeze) and +14% D7 retention (Streak Wager) — [Duolingo blog](https://blog.duolingo.com/how-duolingo-streak-builds-habit); [Duolingo engineering](https://making.duolingo.com/how-streaks-keep-duolingo-learners-committed-to-their-language-goals).
- Material 3 Expressive's publicised "4× faster to spot key elements" shows how eye-tracking/time-to-target metrics are used to sell a design change — [Android Authority](https://www.androidauthority.com/google-material-3-expressive-details-3554486/).

### Inferences
1. **In-app "UX lab" overlay (demo feature)** — a hidden dev toggle that shows live metrics: time on task, clicks/taps, errors, backtracks. Record baseline (a typical competitor flow or your v0) vs final; display a before/after bar chart in the video ("Booking: 11 taps → 4 taps; 94 s → 31 s; SUS 61 → 84").
2. **Micro-study protocol for a hackathon** — 5–8 peers, 3 core tasks, SEQ after each, SUS at end, think-aloud notes; report medians and ranges honestly (small n). Frame with HEART: pick Task success + Happiness.
3. **Instrumentation** — lightweight event logger (PostHog/Plausible or a custom `performance.now()` logger) capturing `task_start`, `task_complete`, `error_shown`, `undo_used`, `ai_override`. Show Web Vitals (INP < 200 ms) for "feel."
4. **Accessibility metrics** — Lighthouse/axe score before/after, contrast ratios, keyboard-only completion time; screen-reader task success.
5. **AI metrics** — % plans edited before run, override rate, undo rate on agent actions, % answers with verified citations — signals of calibrated trust.

### Gaps
- The SEQ "90%+ sensitivity" claim found was vendor-sourced and unverified (excluded).
- No published benchmarks found specifically for hackathon-scale (n≈5) before/after studies; small-sample caveats should be stated.

## 8. Which patterns are most "demo-able" and impressive to hackathon judges in a 2–3 minute video?

### Takeaway
Judges typically score originality, practicality, usability (UI/UX), technical execution and a "wow" factor, and videos are often capped at 2–4 minutes; the best demo candidates are patterns with an instant visible transformation and a measurable payoff: generative UI cards, an editable agent plan with timeline + undo, a one-tap "Adapt to me"/Easy Read/vernacular voice transformation, offline-and-nothing-breaks, optimistic UI vs spinner side-by-side, and a dark-pattern "fairness receipt" — each closed with a before/after metric.

### Cited Findings
- Devfolio's judging guide suggests scoring technicality, originality, practicality, usability (UI/UX/DX) and "wow" factor, noting organisers may use their own rubric — [Devfolio judging guide](https://guide.devfolio.co/docs/guide/participating-in-hackathons/judging-1). ETHGlobal uses similar criteria ("can users easily interact with the solution") and requires 2–4 minute demo videos (out-of-range uploads auto-rejected) — [ETHGlobal Superhack details](https://ethglobal.com/events/superhack/info/details).
- Read the rubric before the problem statement; if UX is 25% of score, polish isn't wasted — [HackerEarth](https://www.hackerearth.com/blog/10-tips-win-hackathon).
- Open with the working product; structure problem → solution → demo → impact; show the one core action; record a backup video; don't show code editors/terminals — judges care about experience — [Reskilll demo tips (2026)](https://blogs.reskilll.com/hackathon-demo-presentation-tips-pitch-3-minutes-win-2026/); [Reskilll guide](https://reskilll.com/blogs/how-to-win-a-hackathon-in-2026-reskillls-guide-from-5000-events/).
- Peak-end rule: experiences are remembered by their peak and end — applicable to demo storytelling — [Laws of UX](https://lawsofux.com/index.md).
- Timeliness hooks for 2026 judges: generative UI went mainstream with Gemini 3 (Nov 2025) — [Google Research](https://research.google/blog/generative-ui-a-rich-custom-visual-interactive-user-experience-for-any-prompt/); EU AI Act Art. 50 AI-disclosure duties from 2 Aug 2026 — [Cooley](https://www.cooley.com/news/insight/2026/2026-08-03-eu-ai-act-transparency-obligations-take-effect-2-august-2026); India CCPA dark-pattern self-audit advisory (June 2025) — [AZB](https://www.azbpartners.com/bank/central-consumer-protection-authority-issues-advisory-to-e-commerce-platforms-for-self-audit-to-detect-dark-patterns-on-their-platforms/); Material 3 Expressive / Liquid Glass visual shifts (2025) — [Android Authority](https://www.androidauthority.com/google-material-3-expressive-details-3554486/); [Macworld](https://www.macworld.com/article/2807925/meet-liquid-glass-apple-redesigns-all-its-interfaces-at-once.html).
- Prototyping speed: Figma Make (prompt-to-code prototypes) and Figma Sites (publish) from Config 2025 — [Digidop](https://www.digidop.com/blog/figma-announces-figma-sites-and-thats-not-all); same-document View Transitions are Baseline (Oct 2025) — [web.dev](https://web.dev/blog/same-document-view-transitions-are-now-baseline-newly-available); AI SDK typed tool parts make generative UI a few components of work — [AI SDK docs](https://ai-sdk.dev/docs/ai-sdk-ui/generative-user-interfaces).

**Suggested 2:30 video storyboard (inference):**
- 0:00–0:15 Problem + persona (use persona spectrum: permanent/temporary/situational user).
- 0:15–1:30 Core flow in one continuous take: voice/intent input → editable plan → generative UI cards → agent timeline with approval gate → optimistic updates → undo.
- 1:30–2:00 Inclusion moment: flip "Adapt to me" (Easy Read + focus + high contrast), then airplane-mode resilience.
- 2:00–2:20 Trust moment: fairness receipt + uncertainty/citation chip + AI disclosure label.
- 2:20–2:30 Peak-end close: before/after metrics chart + celebratory success state.

**Accessibility guardrails to mention explicitly (judges increasingly check):** every animation respects `prefers-reduced-motion`; text contrast ≥4.5:1 even over glass/blur; all generated UI keyboard-navigable with live-region announcements; voice is never the only input; undo toasts don't auto-dismiss while focused; no colour-only status in timelines.

**Pitfalls to avoid:** over-claiming AI confidence with fake percentages (HAX 2A/2B); decorative citations nobody can verify (NN/g); novel skeleton screens (Viget); Liquid-Glass-style blur that fails contrast; dyslexia fonts presented as a fix (Wery & Diliberto); auto-adapting layouts without user control (predictability for autistic users).
